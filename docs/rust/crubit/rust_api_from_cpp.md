# `rust_api_from_cpp`

## Introduction

`rust_api_from_cpp` (aka `rs_bindings_from_cc`) is a Crubit tool that takes
C++ headers as input and generates Rust APIs (a Rust crate) as output,
enabling Rust to call C++.
This document provides instructions for using `rust_api_from_cpp` in Chromium.

See [`//docs/rust/crubit/README.md`](./README.md) for general information about
Crubit, including Crubit availability in projects other than Chromium.

## Availability

`rust_api_from_cpp` support is currently considered experimental and unstable.
The `rust_api_from_cpp` GN template can only be used when the
`enable_rust_api_from_cpp` GN arg is `true`.  It defaults to `false` (see
`//build/config/rust.gni`), but can be set to `true` in `args.gn` for local
experimentation.

## Generating Rust bindings for a C++ target

Use the `rust_api_from_cpp` template to generate Rust bindings for the public
headers of a C++ target.

Example:

```cpp
// build/rust/tests/test_rust_api_from_cpp/self_contained_target_header2.h:
int AddViaCc(int x, int y);

struct CcPodStruct final {
  int value;
};
```

```gn
# build/rust/tests/test_rust_api_from_cpp/BUILD.gn

import("//build/rust/rust_api_from_cpp.gni")
import("//build/rust/rust_static_library.gni")

source_set("self_contained_target") {
  sources = [
    "self_contained_target_header2.cc",
    "self_contained_target_header2.h",
  ]
}

rust_api_from_cpp("self_contained_target_rs_api") {
  # This is the C++ target that the bindings are for / call into.
  bindings_target = ":self_contained_target"

  # Public headers from `sources` of `self_contained_target`.
  public_headers = [
    "self_contained_target_header2.h",
  ]
}

rust_static_library("test_rust_api_from_cpp") {
  crate_root = "tests.rs"
  sources = [ crate_root ]
  deps = [ ":self_contained_target_rs_api" ]
}
```

```rust
// build/rust/tests/test_rust_api_from_cpp/tests.rs:

chromium::import! {
    "//build/rust/tests/test_rust_api_from_cpp:self_contained_target_rs_api";
}

fn foo() {
    let sum = ::self_contained_target_rs_api::AddViaCc(100, 42);
    let x = ::self_contained_target_rs_api::CcPodStruct { value: 123 };
}
```

Notes:

* By convention, a `rust_api_from_cpp` target is named after its
  `bindings_target` with an `_rs_api` suffix (e.g. `foo_rs_api` for `foo`).
* `public_headers` lists only the headers that provide the public API of the
  `bindings_target`.  Rust bindings are generated only for these headers.

## Inspecting the generated bindings

Let's assume that `rust_api_from_cpp` bindings are generated by
`//some/dir:foo_rs_api`.  The generated bindings can then be found and
inspected in `<out_dir>/gen/some/dir/foo_rs_api.rs`.  For example:

```sh
$ head -3 out/rel/gen/build/rust/tests/test_rust_api_from_cpp/self_contained_target_rs_api.rs
// Automatically @generated Rust bindings for the following C++ target:
// //build/rust/tests/test_rust_api_from_cpp:self_contained_target_rs_api
// Features: supported, types
```

## Troubleshooting

The sections below should help diagnose and fix some issues you may encounter.
If your issue is not covered, then please see
[`docs/rust/crubit/README.md`](./README.md) for instructions
how to report a new bug.

### APIs missing from the generated bindings

If `rust_api_from_cpp` is unable to generate bindings for a given C++ API,
then the generated `.rs` file will contain a comment explaining why.

### Different bindings on different target platforms

Public API of Crubit-generated bindings should be the same on all target
platforms.  There are some known issues where the bindings may differ (e.g. see
Google-internal b/564616479), but please do not work around the differences with
something like `#[cfg(windows)]` - please report bugs instead.

# Test Expectations File.
#
# Format:
# crbug.com/<###> [ [Tags] ] TestName [Expectations]
#
# Tag Matching Semantics:
# - OS and Device tags use ANY (OR) matching semantics: If an expectation
#   specifies multiple OS tags (e.g., [ iOS17 iOS18 ]) or multiple device tags
#   (e.g., [ iPhone iPad ]), matching ANY tag within that category satisfies the
#   category requirement.
# - Other tags use ALL (AND) matching semantics: EVERY tag belonging to the
#   "Other" category (e.g., [ Simulator Debug ASan ]) present in the expectation
#   must be active for the expectation to apply.
#
# Supported Tags (case-insensitive):
# - OS Version (supports hierarchical and partial version strings):
#   - Major version: e.g., iOS18, iOS26
#   - Major.Minor version: e.g., iOS18.1
#   - Full version: e.g., iOS18.1.2
#   - Build number: e.g., build-24A5355p (prefixed with 'build-')
#
# - Device Family and Model (supports hierarchical and partial model strings):
#   - Family: iPhone, iPad
#   - Model prefix (without revision suffix): e.g., iPhone16, iPad14
#   - Exact hardware model: e.g., iPhone16,1, iPad14,3
#
# - Other Supported Tags:
#   - Environment: Simulator, Device
#   - Build configuration: Debug, Release
#   - Sanitizer: ASan
#   - Platform: Catalyst
#
# Expectations: Failure, Pass, Crash, Skip
#
# - [ Failure ]: The test runs and fails 100% of the time. This is a strict
#   expectation: if the test ever passes, the run is reported as a failure
#   ("unmet test expectation"), which prompts the gardener to remove the entry.
#   Because of this, scoped [ Failure ] entries are self-cleaning and preferred
#   over [ Pass Failure ] whenever the failure is deterministic.
# - [ Pass Failure ]: The test is flaky; it passes and fails intermittently on
#   the SAME configuration. Do not use this for a test that fails reliably on
#   one configuration and passes reliably on others. Always scope flaky
#   expectations with tags to the configurations where the flakiness was
#   actually observed (e.g. [ iPad Simulator ] ... [ Pass Failure ]) to keep
#   the other configurations reporting.
# - [ Crash ]: The test crashes 100% of the time (uncaught exception or app
#   crash). Combine with Pass and/or Failure for intermittent crashes
#   (e.g. [ Pass Crash ], [ Pass Failure Crash ]).
# - [ Skip ]: The test is not run at all. Reserve this for tests that hang,
#   time out, or consume excessive resources. Skip takes precedence over any
#   other expectation on the same line.
#
# Examples:
# crbug.com/123456 [ iOS26 Simulator Debug ] MyTestCase/testAppStoreSearch [ Failure ]
#     -> Expects MyTestCase/testAppStoreSearch to fail every time on debug builds on an iOS26
#        Simulator.
# crbug.com/789101 [ iOS17 iOS18 iPhone ] FlakyTestCase [ Pass Failure ]
#     -> Expects FlakyTestCase to pass or fail (but never crash) on iPhone devices and
#        simulators running iOS versions 17 or 18.
# crbug.com/234567 [ iPhone16,1 ASan ] CrashingTestCase/testMethod [ Crash ]
#     -> Expects CrashingTestCase/testMethod to crash every time on ASAN builds running on
#        iPhone16,1 (iPhone 15 Pro) devices and simulators.
# crbug.com/345678 [ Device ] HangingTestCase/testMethod [ Skip ]
#     -> Never runs HangingTestCase/testMethod on physical devices (e.g. because it hangs
#        until the test runner times out).
#
